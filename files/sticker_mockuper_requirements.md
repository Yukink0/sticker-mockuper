# Sticker Mockuper（仮称）要件定義書

## 1. 目的・背景

MacBookやiPadにステッカーを貼る前に、実際にどう見えるかをシミュレーションできるWebツール。
既存のステッカーモックアップツール（Canva、Mockeyなど）は「販売者が商品写真を作る」ためのもので、
「個人が自分の端末に、購入前のステッカーを試し貼りする」用途に特化したツールは存在しない。

まずは需要検証のためのMVP（最小限の動くデモ）を作成する。

## 2. 想定ユーザー

- 自分のMacBook / iPadにステッカーを貼りたいが、失敗したくない個人ユーザー
- 手元にステッカーの画像（写真 or ネットで見つけた画像）を持っている人

## 3. スコープ（このMVPで作るもの）

### 3.1 画面構成

1画面完結のWebアプリ。左サイドバー＋右側メイン領域の2カラム構成。

**左サイドバー**
- デバイス選択（PC / iPad の2種類。「スーツケース」ボタンは表示するが、クリックしても何も起きない状態でよい＝将来対応の見せ方だけ用意）
- 「PC」選択時のみ、続けてメーカー選択を表示（MacBookバージョン / Surfaceバージョンの2種類）
  - MacBookバージョン：モックアップ中央に🍎（Appleロゴ）を表示
  - Surfaceバージョン：モックアップ中央にWindowsの窓マークを表示
- サイズ選択（PC選択時のみ表示。選択中のメーカーに応じて選べるサイズの選択肢が変わる。iPad選択時は非表示）
  - MacBookバージョン：13inch / 14inch / 16inch
  - Surfaceバージョン：13.5inch / 15inch
- ステッカー画像アップロードボタン（複数枚選択可）
- アップロード済みステッカーのサムネイル一覧（各サムネイルに削除ボタン（×）付き）
- 「全て削除」ボタン（アップロード済みステッカー・配置済みステッカーを全てクリア）

**右側メイン領域**
- 選択中のデバイス・サイズに応じたモックアップ枠（矩形でよい。中央に薄いロゴ的な装飾があると望ましいが必須ではない）
- サムネイルをドラッグ&ドロップでモックアップ内に配置できる

### 3.2 機能要件

| # | 機能 | 詳細 |
|---|---|---|
| F1 | デバイス選択 | PC / iPad をボタンで切り替え。選択中のボタンがわかるようハイライト表示 |
| F1-2 | メーカー選択（PC選択時のみ） | 「MacBookバージョン」「Surfaceバージョン」の2つから選ぶ。選択に応じてモックアップ中央のロゴ（🍎 / Windows窓マーク）が切り替わる |
| F2 | サイズ選択 | 選択中のメーカーに応じて選べるサイズが変わる（MacBook：13/14/16inch、Surface：13.5/15inch）。サイズに応じてモックアップ枠の縦横比・大きさが、実機に近い比率で変わる（下記6.参照） |
| F3 | 画像アップロード | `<input type="file">` でローカル画像を読み込み、ブラウザ内（クライアントサイド）でのみ処理する。サーバーには送信しない |
| F4 | サムネイル一覧表示 | アップロードした画像を一覧表示。各サムネイルは `draggable` 属性でドラッグ可能にする |
| F5 | サムネイル削除 | サムネイル上の×ボタンでアップロード一覧から削除できる |
| F6 | ドラッグ&ドロップ配置 | サムネイルをモックアップ枠にドロップすると、ドロップした位置にステッカー画像が配置される（HTML5 Drag and Drop APIを使用） |
| F7 | 配置済みステッカーの移動 | 配置済みステッカーをクリック＆ドラッグでモックアップ枠内を自由に移動できる |
| F8 | 配置済みステッカーの拡大縮小 | 選択中のステッカーの右下にリサイズハンドルを表示し、ドラッグでサイズ変更できる |
| F9 | 配置済みステッカーの削除 | 選択中のステッカーの右上に削除ボタン（×）を表示し、クリックで削除できる |
| F10 | 全削除 | 「全て削除」ボタンで、アップロード済み一覧・配置済みステッカーを全てリセットする |
| F11 | 画像として保存 | 完成したモックアップをPNG画像としてダウンロードできる（`html2canvas` 等のライブラリを利用） |

### 3.3 非機能要件

- サーバーサイドの実装は不要。フロントエンドのみで完結させる（画像はブラウザメモリ内のみで処理し、外部に送信しない＝プライバシー面のセールスポイントにもなる）
- レスポンシブ対応は必須ではない（まずはPCブラウザでの利用を想定。スマホ対応は反応を見てから検討）
- ページを再読み込みするとデータは消えてよい（保存機能はMVPでは不要）

## 4. スコープ外（このMVPでは作らないもの）

- 背景除去（透過処理）の自動化 → ユーザーが事前に透過PNGを用意する前提とする
- ログイン機能・アカウント機能
- クラウドへの保存・複数デバイス間の同期
- 実寸（mm単位）での正確なスケール換算機能
- モバイルアプリ化

## 5. 技術要件（指定）

- フロントエンド：React（Vite等の軽量な構成）
- 状態管理：React標準のuseState等で十分。外部の状態管理ライブラリは不要
- ドラッグ&ドロップ：ライブラリを使わず、HTML5標準のDrag and Drop API / mouseイベントで実装（軽量さを優先）
- 画像のダウンロード：`html2canvas` などクライアントサイドで完結するライブラリを使用
- ホスティング：Vercelにデプロイ可能な構成にする（サーバーレス、ビルドコマンドは標準的なもの）
- バックエンド・データベース：なし

## 6. 参考：デバイスごとのアスペクト比

モックアップ枠の縦横比は、以下の実機の天板寸法（目安）を参考に、比率をそのままpx換算して実装する。
実寸そのもの（mm単位の正確な表示）を再現する必要はなく、「サイズを変えると見た目の縦横比も実機らしく変わる」ことが目的。

| メーカー | サイズ | 目安の天板寸法（横×縦, mm） | 縦横比（横:縦） |
|---|---|---|---|
| MacBook | 13inch | 304 × 212 | 約1.43 : 1 |
| MacBook | 14inch | 313 × 221 | 約1.42 : 1 |
| MacBook | 16inch | 356 × 248 | 約1.44 : 1 |
| Surface | 13.5inch | 308 × 223 | 約1.38 : 1 |
| Surface | 15inch | 339 × 244 | 約1.39 : 1 |

※上記の数値は目安であり、実装時にClaude Codeが最新の実機寸法を調べ直しても構わない。重要なのは「MacBookは横長寄り（16:10に近い比率）」「Surfaceはやや正方形に近い比率（3:2に近い比率）」という違いが視覚的に伝わることである。

## 7. 参考：機能イメージ

添付のスクリーンショット（手描きスケッチ）、および会話内で確認した動作プロトタイプの通りの挙動を実装してほしい。
具体的には「デバイス・サイズを選ぶ → ステッカー画像をアップロードする → サムネイルをモックアップにドラッグして配置する → 位置調整・拡大縮小・削除ができる → 全体をリセットできる」という一連の流れ。

## 8. 検証したいこと（今回の開発の目的）

これは事業化に向けた需要検証のためのMVPである。見た目の完成度よりも「実際に動く」ことを優先し、
最短で公開できる状態を目指す。公開後の反応（利用状況、SNSでの反応等）を見て、次の機能拡張（背景除去の自動化、実寸対応、B2B向け埋め込みウィジェット化等）を判断する。
